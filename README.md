# Product & Inventory Microservices

A Spring Boot microservices application consisting of a **Product Service** and an **Inventory Service**. The Product Service manages products and communicates with the Inventory Service to retrieve inventory information when requesting product details.

## Technologies

- Java 21
- Spring Boot
- Maven Wrapper
- JUnit 5
- Mockito
- MockMvc
- JaCoCo
- Lombok

## Prerequisites

- Java 21
- A terminal or command prompt

The project includes the Maven Wrapper generated by Spring Initializr, so Maven does not need to be installed separately.

## Building the Services

The Maven Wrapper can be used to build each service without requiring a separate Maven installation.

**Product Service** — from the `product-service` directory:
```
.\mvnw.cmd clean verify
```

**Inventory Service** — from the `inventory-service` directory:
```
.\mvnw.cmd clean verify
```

The `verify` command compiles the project, runs the automated tests, and executes the configured Maven verification steps.

## Running the Services

Both services can be started using the Maven Wrapper. **Both should be running** when testing the Product Service endpoint that retrieves product details including inventory information.

**Inventory Service** — runs on `http://localhost:8082`, from the `inventory-service` directory:
```
.\mvnw.cmd spring-boot:run
```

**Product Service** — runs on `http://localhost:8081`, from the `product-service` directory:
```
.\mvnw.cmd spring-boot:run
```

## API Endpoints

### Product Service

**Get all products**
```
GET /products
```
```
curl http://localhost:8081/products
```

**Get a product by ID**
```
GET /products/{id}
```
```
curl http://localhost:8081/products/1
```

**Create a product**
```
POST /products
Content-Type: application/json
```
```
curl -X POST http://localhost:8081/products ^
-H "Content-Type: application/json" ^
-d "{\"name\":\"Phone\",\"price\":899.99}"
```
Example response:
```json
{
  "id": 4,
  "name": "Phone",
  "price": 899.99
}
```
> The request is validated before a product is created. Invalid requests return `400 Bad Request`.

**Get product details including inventory**
```
GET /products/{id}/details
```
```
curl http://localhost:8081/products/1/details
```
Example response:
```json
{
  "id": 1,
  "name": "Laptop",
  "price": 999.99,
  "quantity": 20
}
```
This endpoint demonstrates communication between the two microservices: the Product Service retrieves the product from its own repository and requests the corresponding inventory information from the Inventory Service.

### Inventory Service

**Get inventory by product ID**
```
GET /inventory/{productId}
```
```
curl http://localhost:8082/inventory/1
```
Example response:
```json
{
  "productId": 1,
  "quantity": 20
}
```
> If no inventory record exists for the requested product, the service returns `404 Not Found`.
```
curl http://localhost:8082/inventory/999
```

## Implementation Assumptions

The following assumptions and shortcuts were made to keep the implementation within the one-working-day scope of the assignment.

**Service-to-service communication**
The Product Service communicates with the Inventory Service using `RestTemplate`. When requesting `GET /products/{id}/details`, the Product Service first retrieves the product locally, then requests the corresponding inventory information from the Inventory Service.

**Local service configuration**
The Inventory Service URL is hardcoded in the Product Service as `http://localhost:8082`, to keep the implementation simple and avoid additional configuration.

**No persistence**
Products and inventory records are predefined in memory. Creating a product changes the in-memory state only and does not persist data after the service restarts.

## Separation of Concerns

The application separates responsibilities into different layers:

| Layer          | Responsibility |
|-----------------|-----------------|
| **Controller**  | Handles HTTP requests and responses |
| **Service**     | Contains application and business logic |
| **Repository**  | Handles access to the in-memory data |
| **Model**       | Represents the application's data |
| **DTO**         | Used by the Product Service for request data and communication with the Inventory Service |
| **Exception**   | Contains application-specific exceptions and error handling |

This separation makes the code easier to test and allows individual components to be changed without affecting the other layers.
